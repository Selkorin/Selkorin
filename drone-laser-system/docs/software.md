# Программное обеспечение

ПО написано на Python (пакет `dls`) и разбито на слои с чёткими границами.
Весь конвейер запускается в симуляторе без оборудования (`python -m dls --sim`).

## Карта модулей

| Модуль | Ответственность | Ключевые типы/функции |
|--------|-----------------|-----------------------|
| `dls.config` | Загрузка/валидация конфигурации | `Config`, `load_config` |
| `dls.detection` | Поиск целей на кадре | `Detector`, `Detection` |
| `dls.tracking` | Сопровождение и геометрия | `Tracker`, `KalmanFilter2D`, `pixel_to_angles` |
| `dls.control` | Управление приводом | `Gimbal`, `PID`, `*GimbalHAL` |
| `dls.laser` | Управление лазером | `Laser`, `*LaserBackend` |
| `dls.safety` | Блокировки и разрешение огня | `SafetyManager`, `FireRequest` |
| `dls.core` | Оркестратор и автомат | `Orchestrator`, `SystemState` |
| `dls.sim` | Синтетический стенд | `SyntheticScene`, `run_sim` |

## Ключевые алгоритмы

### 1. Обнаружение (`detection/detector.py`)
Вычитание фона + пороговая обработка + разметка связных компонент; фильтрация
по площади. Работает через OpenCV (MOG2), а при его отсутствии — на чистом numpy
(фон как экспоненциальное скользящее среднее), что позволяет запускать конвейер
и тесты без установки OpenCV.

### 2. Сопровождение (`tracking/`)
Каждая цель сглаживается фильтром Калмана с моделью постоянной скорости
(состояние `[x, y, vx, vy]`). Многоцелевой трекер ассоциирует детекции с треками
по ближайшему в окне (`gate_px`) и подтверждает трек после нескольких попаданий,
что отсекает шум.

### 3. Компенсация собственного движения камеры (ego-motion)
Камера установлена на приводе, поэтому при повороте неподвижная в мире цель
смещается в кадре. Перед ассоциацией оркестратор сдвигает позиции всех треков на
величину, соответствующую повороту привода между кадрами
(`Tracker.shift`). Без этого сопровождение в системе координат кадра расходится
(цель «убегает» из окна ассоциации при быстром наведении).

### 4. Пересчёт координат (`tracking/coordinates.py`)
Модель камеры-обскуры: пиксель `(u, v)` → угловое смещение от оптической оси →
целевые углы привода = текущие углы + смещение + поправка боресайта, с учётом
ограничений хода.

### 5. Наведение (`control/`)
PID по угловой ошибке выдаёт угловую скорость (град/с), ограничивается
`max_speed_deg_s` и интегрируется в новую командную позицию. Интегральный член
устраняет ошибку слежения за целью с постоянной скоростью. Есть anti-windup и
ограничение выхода.

### 6. Безопасность (`safety/safety.py`)
Единая точка `SafetyManager.evaluate`. Огонь разрешается только при выполнении
ВСЕХ условий (взведение ключом, отсутствие E-STOP, свежий watchdog, вне зон
запрета огня, тепловой режим, лимит времени; для режима eliminate — ближняя зона,
отсутствие человека, освещённость, классификация «насекомое»). См. [../SAFETY.md](../SAFETY.md).

## Главный цикл (`core/orchestrator.py`)

```
step(frame, dt, sensors):
  1. обновить входы безопасности, сбросить watchdog
  2. если E-STOP / не взведён -> SAFE (лазер off, треки сброшены)
  3. ego-компенсация треков по повороту привода
  4. детектор -> трекер -> выбор/удержание цели
  5. предсказать положение цели -> целевые углы
  6. PID-наведение привода
  7. если наведён -> SafetyManager.evaluate -> (разрешено) лазер.fire / (нет) off
```

Инвариант: `Laser.fire` вызывается только после `SafetyDecision.permitted == True`.

## Перенос на реальное оборудование

1. В `config/system.yaml` установить `gimbal.backend: serial`, `laser.backend: serial`,
   указать `serial_port`; задать реальный индекс камеры и калиброванные
   `fx, fy, cx, cy`.
2. Гимбал и лазер разделяют один `SerialLink` (см. `build_system`).
3. В `dls/__main__.py::_run_hardware` в месте `# TODO` подставить чтение реальных
   датчиков (E-STOP, ключ, освещённость, PIR, дальномер) в `SensorInput`.
4. Прошить контроллер осей (`hardware/firmware/gimbal_controller`).
5. Выполнить калибровку по [calibration.md](calibration.md).

## Тесты

`pytest -q` — модульные тесты (PID, Калман, координаты, безопасность, трекер) и
сквозной тест конвейера в симуляторе (`test_integration.py`).
